# 0004 EMA 级联指标与随机指标迁移

## 背景

在前两波 Rust 迁移之后，这个仓库已经覆盖了：

- 基础均线
- 常见 oscillator
- 多输出指标
- 多输入指标

但还有一类典型复杂指标没有覆盖：基于多层 EMA 级联的指标，以及带窗口最高/最低追踪和双层平滑的随机指标。

这类指标的重要性在于，它们会逼着迁移框架回答两个更难的问题：

- 当前 Rust 结构能不能承载多阶段递推状态
- 当前 benchmark 基础设施能不能反映这些更复杂算法的性能特征

所以这次提交不是单纯地“再多搬几个指标”，而是继续验证 Rust 核心是否能支撑更复杂的指标族。

## 主要目标

这次提交主要有三个目标：

1. 迁移 `dema`、`tema`、`trix`、`stoch`
2. 让这些新指标自动进入 registry、golden test 和 benchmark
3. 继续扩大 Rust 覆盖面，同时保持现有 C 路径完全稳定

这一步完成后，Rust 侧就不再只覆盖“普通指标”，而是开始覆盖更具代表性的组合型和窗口型实现。

## 改动概览

这次新增了四个 Rust 指标实现：

- `dema`
- `tema`
- `trix`
- `stoch`

可以把它们分成两组来理解。

第一组是 EMA 级联家族：

- `dema`
- `tema`
- `trix`

它们的共同点是都不是简单的一层平滑，而是多层 EMA 串联后再组合输出。
这类指标非常适合用来验证 Rust 实现是否正确保留了 C 版本里的 warm-up 边界和输出起点。

第二组是随机指标：

- `stoch`

它的难点不在 EMA，而在于：

- 维护窗口内最高值
- 维护窗口内最低值
- 做 `%K` 的平滑
- 再对 `%K` 做 `%D` 平滑

这意味着它既有窗口维护问题，也有多阶段平滑问题。

除了指标本身，还做了两件基础设施层的事情：

- 把新指标接进 Rust registry
- 给 benchmark 的默认参数生成补齐了 `k_period` / `k_slowing_period` / `d_period`

所以新增指标后，不需要再额外改 benchmark 才能出数。

## 关键知识

### 1. 为什么 `dema` / `tema` / `trix` 要一起迁

这三个指标在实现思路上高度相关：

- 都建立在多层 EMA 之上
- 都依赖明确的 warm-up 区间
- 都非常容易因为“输出从哪里开始”而出现 off-by-one 错误

把它们放在同一波迁移，最大的好处是可以连续验证：

- 两层 EMA 的边界处理
- 三层 EMA 的边界处理
- 三层 EMA 后再做变化率输出的边界处理

如果这三者都能通过 golden data，对后续更多级联型指标会更有信心。

### 2. 为什么 `stoch` 需要特别关注性能

`stoch` 不是简单地算一遍就结束，它每一步都依赖一个滑动窗口内的最大值和最小值。

如果实现方式太朴素，性能会很容易掉下去。

这次 Rust 版本没有用最简单的“每一步都全窗口重扫”，而是沿用了 C 版的思路：

- 当前最大值/最小值还在窗口里时直接复用
- 只有它们滑出窗口时才重扫当前区间

这样 benchmark 才更有参考价值，不会因为明显低效的实现把后续优化空间判断搞偏。

### 3. 为什么 benchmark 要自动包含这些新指标

复杂指标迁移后，如果 benchmark 不自动跟上，会有两个坏结果：

- 性能变化不可见
- 新迁移指标会长期处在“功能对了，但性能没人看”的状态

这次把参数生成补齐后，新增复杂指标也能直接进入 benchmark。
这正是“持续自动迭代优化”的前提。

## 验证

这次实际运行了：

- `cargo fmt`
- `cargo test`
- `cargo run --release --bin indicator-bench`
- `./smoke`

结果上：

- Rust golden test 通过
- 新增指标都进入了 release benchmark 输出
- 旧 C 测试路径仍然通过

这说明当前迁移既没有破坏既有行为，也没有把 benchmark 链条打断。

## 未覆盖项

这次还没有处理这些内容：

- `dema`、`tema`、`trix`、`stoch` 还没有 Rust 流式实现
- benchmark 依然只测 Rust 版本，不对比 C 版本
- 还没有建立 benchmark 历史基线或自动回归阈值
- 更复杂的派生指标，如 `stochrsi` 等，还没有跟进迁移

## 对新手的理解建议

可以把这次提交看成“把 Rust 迁移推进到组合型指标阶段”。

前面的迁移更多是在证明：

- 基础抽象能不能工作
- 常见指标能不能对齐

而这次开始证明：

- 多层 EMA 级联能不能稳定迁移
- 窗口维护型指标能不能既正确又保持合理性能

如果未来继续往更复杂指标推进，这次会是一个很重要的参考点。
