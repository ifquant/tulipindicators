# 迁移中等复杂度振荡器与均线

## 这次改动的背景

上一批我们批量迁掉了大量规则型指标，把 Rust 覆盖率从 `24 / 104` 提到了 `61 / 104`。  
接下来最自然的一步，不是回去做特别难的大指标，而是继续吃掉一批“中等复杂度、但很能复用现有骨架”的指标。

这类指标的特点是：

- 比 `abs`、`sum`、`crossany` 这类规则型指标更复杂
- 但又不需要像 `macd`、`stoch`、`adx` 那样重新设计很多状态机
- 大部分都可以建立在已经验证过的 `EMA`、`ATR`、窗口极值、双层均值和 RingSum 之上

所以这次的目标很明确：继续扩展覆盖率，但尽量复用现有 Rust 核心结构。

## 这次迁移了哪些指标

### Indicator

- `apo`
- `ppo`
- `natr`
- `willr`

### Overlay

- `vwma`
- `trima`
- `zlema`

## 这批指标为什么适合现在做

### 1. `apo` / `ppo`

它们本质上都是双 EMA 差值家族。

- `apo` 是短 EMA 减长 EMA
- `ppo` 是短 EMA 与长 EMA 的百分比差

这意味着我们可以直接复用前面已经验证过的 `EmaState`，只是在输出组合公式上不同。

### 2. `natr`

它本质上是 `ATR` 的标准化版本。

也就是说，难点不是“怎么重新发明波动率算法”，而是：

- 保持和 `ATR` 一样的平滑逻辑
- 最后按当前 `close` 去归一化

这种指标很适合放在当前阶段，因为它能证明 Rust 实现已经开始具备“从已有骨架派生新指标”的能力。

### 3. `willr`

`Williams %R` 和随机指标族很接近，本质都依赖窗口内最高价/最低价。

我们前面已经在 `stoch` 里验证了基于单调队列维护窗口极值的写法，所以这次只需要复用同类思路，而不需要回到 C 版那种手动追踪 `maxi` / `mini` 的写法。

### 4. `vwma`

`VWMA` 是一个非常典型的“两个滚动和组合输出”的指标：

- 价格乘成交量的滚动和
- 成交量滚动和
- 最后相除

这正好适合复用 `RingSum`。

### 5. `trima`

这次最值得讲的是 `TRIMA`。

表面上看，C 版用了比较绕的权重更新算法，但从概念上它其实就是“两层 SMA”：

- 奇数周期：`SMA(SMA(x, half), half)`
- 偶数周期：`SMA(SMA(x, period/2), period/2 + 1)`

这类改写很适合 Rust 风格迁移，因为它把“难读的原地权重技巧”转成了“更容易解释的组合结构”。

### 6. `zlema`

`ZLEMA` 则是“带延迟补偿的 EMA”。

它不是简单复用普通 EMA，但状态还是比较清晰：

- 保留一个 lag 历史窗口
- 当前值做零滞后补偿
- 再喂入 EMA 更新公式

这类指标说明 Rust 侧现在已经能稳定处理“带历史回看 + 平滑”的中等复杂状态机。

## 这次对架构的意义

这次提交的意义，不只是多了 7 个指标，而是继续证明一件事：

> Rust 侧已经不是单点迁移，而是在开始形成一套可以持续派生新指标的实现框架。

这次新增的 7 个指标，分别复用了：

- `EmaState`
- `true_range`
- `MonotonicQueue`
- `RingSum`
- 双层均值组合

这说明之前做的共享状态抽象不是“为了漂亮”，而是真的开始产生复用收益。

## 覆盖率变化

这次提交后，Rust registry 从 `61 / 104` 提升到 `68 / 104`。

也就是说，稳定指标里已经超过三分之二有 Rust 版本了。

这会直接改变后面的工作方式：

- 剩下的指标更少了
- 未迁移集合更集中在少数更复杂家族
- benchmark 和 golden data 已经能自动覆盖越来越多的 Rust 指标

## 这次验证了什么

实际跑过：

- `cargo fmt --all`
- `cargo test`
- `cargo run --release --bin indicator-bench`
- `make -B smoke`

这说明：

- 新指标的 batch 结果通过现有 golden data
- 新指标的 stream 结果和 batch 保持一致
- benchmark 会自动纳入这批新注册指标
- C 侧原有 smoke 测试链仍然完整通过

## 这次没有做什么

- 还没有继续迁 `ao`、`aroon`、`aroonosc`、`dpo`、`emv`、`mass`、`roc`、`rocr`、`vhf`、`volatility`
- 还没有处理 `psar`、`ultosc`、`mfi`、`kvo` 这类状态更复杂的指标
- 还没有做 C/Rust benchmark 并排对比

## 新手应该怎么理解这次提交

如果上一批是“批量铺基础砖”，这一次就是“开始稳定收中复杂度指标”。

它的价值不在于单个指标有多炫，而在于：

- 继续提高真实覆盖率
- 验证共享状态抽象的复用价值
- 为剩余更复杂指标缩小搜索空间

这就是为什么这次虽然只有 7 个指标，但依然是很关键的一步。
