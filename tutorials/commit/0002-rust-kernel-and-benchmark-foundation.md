# 0002 Rust 内核与性能基准基础设施

## 背景

这个仓库原本完全是 C 工程。
如果直接一次性把所有指标一起改写成 Rust，风险会很高：

- 很难确认哪一步引入了行为偏差
- 很难逐步比较 Rust 和 C 的结果是否一致
- 很难看清性能是变好了还是变差了

所以更稳妥的做法，不是“大爆炸重写”，而是先建立一个最小 Rust 内核，再用少量代表性指标验证架构和测试方式。

这次提交就是这个方向的第一步。

## 主要目标

这次提交想解决三个实际问题：

1. 给 `tulipindicators` 建立一个最小可运行的 Rust crate 骨架
2. 先迁移 `sma` 和 `ema`，验证批处理与流式接口设计是否可行
3. 建立可重复运行的 benchmark 基础设施，为后续持续性能优化提供基线

换句话说，这次不是要完成 Rust 重写，而是要把“以后可以持续迁移和持续优化”的地基先打好。

## 改动概览

这次主要新增了四类内容。

第一类，是 Rust crate 骨架：

- 新增 `Cargo.toml`
- 新增 `src/lib.rs`
- 新增核心模块，定义错误类型、指标元数据、注册表和流式接口

第二类，是首批 Rust 指标实现：

- 迁移 `sma`
- 迁移 `ema`
- 给这两个指标补上批处理与流式运行路径

第三类，是 golden test：

- 新增 Rust 测试，直接复用现有 `tests/*.txt` 文本数据
- 对 `sma` 和 `ema` 做结果对齐校验
- 额外验证流式输出和批处理输出在分块执行时保持一致

第四类，是 benchmark 基础设施：

- 新增统一 benchmark 模块
- 新增 `indicator-bench` 可执行入口
- 对当前 Rust 注册表中的指标统一输出批处理和流式性能
- 把结果写到 `target/indicator-bench/latest.md` 和 `latest.tsv`

## 关键知识

### 1. 为什么先迁移 `sma` 和 `ema`

这两个指标很适合作为第一批：

- 都是单输入单输出
- 一个是窗口类指标（`sma`）
- 一个是递推类指标（`ema`）
- 都容易做批处理和流式对照

如果这两类都能跑通，后续迁移 `bbands`、`rsi`、`macd`、`atr` 时，就已经有比较可靠的模式可以复制。

### 2. 为什么先做最小注册表

当前 C 工程里有一个很大的全局注册表。
Rust 版本暂时不追求“一步到位覆盖全部 104 个指标”，而是先做一个只注册已迁移指标的最小注册表。

这样做有两个好处：

- 已迁移范围非常清楚，不会假装“Rust 版本已经全有了”
- benchmark 和测试可以直接对注册表做遍历，不需要为每个指标单独写入口

### 3. 为什么 benchmark 要现在就做

如果不从一开始就建立 benchmark，后面就会遇到一个典型问题：
代码已经改了很多轮，但没人知道性能到底是改善还是退化。

这次先做 benchmark 基础设施的意义是：

- 每迁移一个指标，都能立刻看到性能数据
- 后续自动迭代优化时，有稳定输出可以比较
- 可以同时观察批处理和流式路径，而不是只看一种模式

这套 benchmark 现在还很基础，但它已经具备“持续使用”的价值。

### 4. 为什么 benchmark 结果写到 `target/`

benchmark 结果需要反复生成，但通常不应该污染仓库历史。
所以这次把输出放在 `target/indicator-bench/`，并把 `target/` 忽略掉：

- 本地跑完就能看结果
- 不会让每次 benchmark 都弄脏工作树
- 后面如果要引入历史对比，再决定是否把某些结果另存为正式基线

## 验证

这次实际运行了下面这些检查：

- `cargo test`
- `cargo fmt --check`
- `cargo run --release --bin indicator-bench`
- `./smoke`

结果上：

- Rust 测试通过
- Rust 格式检查通过
- benchmark 可以成功输出当前 Rust 指标的性能表
- 旧 C 测试路径仍然通过，没有被 Rust 骨架破坏

## 未覆盖项

这次还没有处理这些内容：

- 还没有迁移 `bbands`、`rsi`、`macd`、`atr`
- Rust 注册表目前只覆盖 `sma` 和 `ema`
- 还没有把 C 实现纳入同一套 benchmark 对比
- 还没有做 benchmark 历史基线比较或自动告警
- 还没有提供 C FFI 兼容层

## 对新手的理解建议

如果你以后看到更多 Rust 迁移提交，可以把这次看作“基础设施提交”：

- 它先定义了 Rust 世界里的最小规则
- 它先建立了正确性校验方式
- 它先建立了性能观察方式

后面的指标迁移，很多都会建立在这次提交打下的框架上。
