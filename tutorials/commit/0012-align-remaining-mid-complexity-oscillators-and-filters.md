# 对齐剩余中等复杂度振荡器与过滤器

## 这次改动的背景

上一批我们已经把 `apo`、`ppo`、`natr`、`willr`、`vwma`、`trima`、`zlema` 迁到了 Rust，覆盖率来到了 `68 / 104`。  
接下来最合理的动作不是立刻去攻最难的 `psar`、`ultosc`、`mfi`、`kvo`，而是先把剩下这一组“还不算最难，但已经明显超出纯规则型指标”的中等复杂度指标收掉。

这批指标的共同点是：

- 已经依赖窗口极值、历史回看、双层平滑或滚动统计
- 但仍然可以建立在当前 Rust 核心的共享状态之上
- 迁完之后，Rust registry 会更接近“多数稳定指标已可用”的状态

所以这次提交的核心目标很直接：

- 继续提高 Rust 对齐率
- 让 batch / stream / benchmark 三条链一起覆盖更多指标
- 在不引入第二套模式的前提下，复用已有共享状态

## 这次迁移了哪些指标

- `ao`
- `aroon`
- `aroonosc`
- `dpo`
- `emv`
- `mass`
- `roc`
- `rocr`
- `vhf`
- `volatility`

迁移完成后，Rust 覆盖率从 `68 / 104` 提升到 `78 / 104`。

## 这些指标为什么适合放在一批

### 1. `ao`

`Awesome Oscillator` 本质上是两个不同窗口的中价均值之差：

- `hl = (high + low) / 2`
- 短窗口 5
- 长窗口 34

这类指标非常适合用 `RingSum` 来做，因为本质只是两个滚动和的组合输出。

### 2. `aroon` / `aroonosc`

这一组的难点不在数值公式，而在“窗口内最高点和最低点的索引维护”。

对新手来说，关键理解是：

- 很多技术指标并不只依赖窗口里的最大值/最小值
- 它们还依赖“那个极值出现在第几根 bar”

这就是为什么这次要在共享状态里补 `MonotonicQueue::front_index()`。  
如果只有 `front_value()`，只能拿到值，拿不到相对时间位置，就没法正确复现 `Aroon` 家族。

### 3. `dpo`

`DPO` 的关键不是均值，而是“偏移后的原始价格”减去当前窗口 SMA。

所以它比普通 `SMA` 多了一层历史回看：

- 当前窗口要维护 `period` 个样本的均值
- 同时还要拿到窗口内某个固定偏移位置的旧值

这类指标很适合讲给新手，因为它能直观看出：

> 有些指标不是只看窗口聚合值，还要把窗口里的某个历史点重新拿出来参与公式。

### 4. `emv`

`EMV` 很适合作为“轻量级三输入指标”的例子。

它需要：

- `high`
- `low`
- `volume`

但状态其实很简单，只要记住上一根 bar 的中点即可。  
这说明“输入维度多”和“状态机复杂”并不是一回事。

### 5. `mass`

`Mass Index` 是这批里最值得重点说明的一个。

它的结构是：

- 先对 `high - low` 做一层 EMA
- 再对这层 EMA 做第二层 EMA
- 再把两者做比值
- 最后对这个比值做滚动求和

也就是说，它是一个非常典型的“级联平滑 + 二次派生 + 窗口汇总”指标。  
这类指标能证明 Rust 核心已经不只是能做单层窗口，而是在稳定承接多阶段状态链。

### 6. `roc` / `rocr`

这两个指标的价值，不在公式有多复杂，而在于它们能复用和 `mom` 类似的“固定 lag 缓冲区”模式。

这说明我们已经开始形成一种更稳定的迁移方法：

- 先识别这个指标属于哪类历史依赖
- 再复用已经存在的那一类状态结构

### 7. `vhf`

`VHF` 是一个很好的“窗口极值 + 相邻变化和”的组合案例。

它同时依赖：

- 当前窗口最大最小值
- 窗口内一串相邻价格变化绝对值的总和

这类指标说明，真实的技术指标经常是多个窗口状态叠加，而不是单一 SMA/EMA 能解决。

### 8. `volatility`

`Volatility` 这次迁移的重点是“收益率窗口”而不是“价格窗口”。

也就是说，滚动的不是原始价格，而是：

- `input[i] / input[i-1] - 1`

然后再对这组收益率做方差和年化缩放。  
这对于新手理解很重要，因为它能帮助区分：

- 价格波动
- 收益率波动

这两者在金融指标里不是同一个概念。

## 这次对 Rust 架构的意义

这次提交不只是多了 10 个指标，更重要的是进一步验证了 Rust 迁移骨架的复用价值：

- `RingSum` 继续支撑多窗口和滚动统计
- `MonotonicQueue` 从“只取值”扩展到“值 + 索引”
- 固定 lag 缓冲区开始稳定复用于 `mom` / `roc` / `rocr`
- 级联 EMA 状态已经能承接 `mass` 这类更像“指标管线”的实现

这说明前面做的共享状态抽象，正在逐步成为真正的迁移基础设施，而不是只服务单个指标。

## 这次验证了什么

实际跑过：

- `cargo fmt --all`
- `cargo test`
- `cargo run --release --bin indicator-bench`
- `make -B smoke`

这意味着：

- 新注册指标已经纳入 Rust golden data 对齐
- 新增 stream 实现和 batch 结果保持一致
- benchmark 报告会自动给这批指标产出性能数据
- C 侧原有 smoke 链仍然通过

## 这次没有做什么

- 还没有继续迁 `psar`、`ultosc`、`mfi`、`kvo`
- 还没有做 C 和 Rust 的并排 benchmark 比对
- `dpo` 的 `period = 1` 这个 C 侧本身就不安全的边界，在 Rust 里没有照搬未定义行为，而是直接拒绝

## 新手应该怎么理解这次提交

如果前几批提交是在“搭地基”和“验证代表性指标模式”，这次更像是在系统清理剩余的中复杂度家族。

它的价值有三层：

- 把 Rust 覆盖率从 `68 / 104` 推到 `78 / 104`
- 证明共享状态已经足够支撑更多真实指标
- 把剩余未迁移集合进一步压缩到更少、更明确的复杂指标上

对人和 AI 协作来说，这很重要。  
因为后面的迁移任务会越来越聚焦，越来越不需要重新摸索“应该怎么写这类指标”，而是直接沿着已经验证过的模式继续推进。
