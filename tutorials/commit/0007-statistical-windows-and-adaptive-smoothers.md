# 0007 统计窗口指标与自适应平滑指标迁移

## 背景

在前几次 Rust 迁移之后，这个仓库已经有了：

- 均线和窗口类基础指标
- `macd`、`bbands`、`stoch` 这类组合型指标
- ADX 家族、`stochrsi`、`wilders`
- batch / stream 对齐测试
- benchmark 基础设施

但还有两块非常常见的能力没有补上：

1. 统计窗口指标
2. 复杂平滑类 overlay

具体说，就是这些稳定指标还没迁到 Rust：

- `stddev`
- `var`
- `stderr`
- `kama`
- `hma`
- `vidya`

这批指标看起来不像 ADX 家族那样“彼此紧密依赖”，但它们背后其实有两套很有价值的共享基础件：

- 滚动二阶矩统计
- 滚动加权平均

如果不把这两套基础件抽出来，后面每来一个统计型或复杂平滑型指标，都要重新写一遍窗口和状态维护。

## 主要目标

这次提交主要解决四件事：

1. 把 `stddev / var / stderr / kama / hma / vidya` 迁进 Rust registry
2. 给这批指标补 batch 和 stream 两条路径
3. 抽出共享的滚动统计状态和 WMA 状态
4. 让 golden test 和 benchmark 自动覆盖这批新增指标

做完之后，Rust 侧就不只是在“补指标数量”，而是在补更通用的数学积木。

## 改动概览

这次新增了 6 个 Rust 指标：

- `stddev`
- `var`
- `stderr`
- `kama`
- `hma`
- `vidya`

同时补了两类共享状态：

- `RollingStatsState`
- `WmaState`

这两个状态分别解决：

- 固定窗口里的 `sum` / `sum2` 维护
- 固定窗口里的加权和递推

有了它们以后：

- `stddev / var / stderr` 可以共享同一套滚动窗口统计
- `hma` 可以用三层 WMA 状态直接表达
- `vidya` 可以在短窗/长窗标准差基础上做自适应平滑

而 `kama` 虽然不直接复用这两个基础件，但它也属于“增量状态比公式本身更重要”的那类指标，所以这次顺手一起收口最合适。

## 关键知识

### 1. 为什么 `stddev / var / stderr` 应该一起迁

这三个指标本质上只差最后一步输出变换：

- `var` 输出方差
- `stddev` 输出方差开根号
- `stderr` 输出标准差再乘 `1 / sqrt(period)`

它们真正共享的核心不是“名字像”，而是都依赖窗口内：

- 和 `sum`
- 平方和 `sum2`

如果这三个分开写，很容易出现：

- 一个指标的窗口更新顺序和另一个不一致
- 一个修了浮点边界，另两个忘了同步

所以这次把它们作为一个子族一起迁，是在保护后续维护成本。

### 2. 为什么 `hma` 需要共享 WMA 状态

`hma` 不是一个单独公式就结束的指标。

它本质上是：

- 先做一次 `WMA(period)`
- 再做一次 `WMA(period / 2)`
- 把两者组合成 `2 * WMA(period/2) - WMA(period)`
- 再对这个结果做一次 `WMA(sqrt(period))`

如果没有共享的 `WmaState`，那 `hma` 的实现里很快就会混进大量“如何维护加权和和窗口”的样板代码，真正的公式反而被淹没。

抽出 `WmaState` 后，`hma` 的主体逻辑就能更直接地表达为三层状态机串联。

### 3. 为什么 `vidya` 和 `kama` 值得一起做

`vidya` 和 `kama` 都属于“自适应平滑”：

- `vidya` 用短窗和长窗的标准差比值调节平滑强度
- `kama` 用 efficiency ratio 调节平滑强度

它们的共同点是：

- 不是固定系数平滑
- 不是固定窗口输出
- 正确与否高度依赖跨输入保存的状态

把它们和统计窗口指标放在同一批迁移，有个很实际的好处：

- `vidya` 直接吃到这次新加的滚动统计基础件
- `kama` 则把“复杂自适应状态机”这条线也补上了

这样这一批提交就不只是多了几个指标，而是把“统计窗口”和“自适应平滑”两条能力线都推进了一步。

### 4. 为什么 stream 对这批指标同样重要

这批指标里，很多人容易只盯着 batch 结果。

但如果真实调用方是分块喂数据：

- `stddev / var / stderr` 需要跨 chunk 保留窗口
- `hma` 需要跨 chunk 保留三层 WMA 状态
- `vidya` 需要跨 chunk 保留短窗、长窗和上一次输出
- `kama` 需要跨 chunk 保留变化和、历史价格和当前自适应值

所以这次不是只做静态公式搬运，而是把它们真正接进了 stream 路径。

## 验证

这次实际运行了：

- `cargo fmt --all`
- `cargo test`
- `cargo run --release --bin indicator-bench`
- `./smoke`

结果上：

- 新增指标全部通过 Rust golden data 对齐
- 新增 stream 路径通过 batch-vs-stream 对齐
- benchmark 成功输出这批指标的 batch / stream 性能数据
- 旧 C 测试路径仍然全部通过

## 未覆盖项

这次还没有处理：

- `wma` 这个公共基础指标本身还没有单独迁进 Rust registry
- 其它复杂平滑类，如 `zlema`、`trima`、`kvo`、`mfi` 等，还没继续跟进
- benchmark 仍然没有做 C 与 Rust 的直接对比，也没有性能回归阈值

## 对新手的理解建议

可以把这次提交看成“Rust 迁移开始补数学积木和自适应平滑”。

前面几次更像是在补：

- 常见指标
- 复杂组合指标
- 趋势家族

而这次更像是在补：

- 统计窗口能力
- 加权窗口能力
- 自适应平滑能力

如果以后要继续迁更多指标，这次最值得记住的不是具体哪 6 个指标，而是新增了哪两类共享状态：

- 滚动统计
- WMA 状态

后面很多指标都可以建立在这两块基础之上。
