# 把默认全量 benchmark 时间压到更实用的级别

这次改动的背景很现实：当前 benchmark 基础设施已经能同时做 `C vs Rust` 和 `Rust vs 自己历史最好` 两层比较了，但默认全量跑的时间太长。这样的默认值不利于高频迭代，因为你每改完一笔都不太愿意立刻再跑一次。

所以这次的目标不是“让 benchmark 更精确”，而是先把默认全量 benchmark 调到一个更实用的时长级别。更稳、更重的口径仍然保留，但改成需要你显式通过环境变量拉高。

## 这次改了什么

默认 benchmark 参数从：

- `TARGET_MS = 1000`
- `CALIBRATION_MS = 50`
- `REPEATS = 5`

调成了：

- `TARGET_MS = 300`
- `CALIBRATION_MS = 20`
- `REPEATS = 3`

Rust 和 C contract benchmark 两边都一起改了，这样默认口径仍然一致，不会出现“一边降采样，另一边没有”的问题。

## 为什么这样改大致能接近原来四分之一

粗略看 benchmark 总时长，可以把它想成：

```text
总时长 ≈ 重复次数 × 每次 sample 时长
```

以前是：

- `5` 次重复
- 每次目标大约 `1000ms`

现在是：

- `3` 次重复
- 每次目标大约 `300ms`

所以量级上大约会变成：

```text
3 × 300 / (5 × 1000) = 0.18
```

也就是默认全量跑的目标时间会压到原来的五分之一左右。实际跑出来不会完全一样，因为还受：

- calibration
- 最小迭代次数
- 不同指标本身的成本

影响，但方向是对的：默认回归检查会明显更快。

## 这样做的设计取舍

这里做的是“默认值调轻”，不是“删掉稳定性能力”。

如果你想做更严肃的性能结论，仍然可以手动拉高：

```bash
TI_BENCH_TARGET_MS=1000 TI_BENCH_REPEATS=5 cargo run --release --bin indicator-bench-compare
```

所以现在变成两档使用方式：

- 日常迭代：直接用默认值，快
- 做正式性能判断：显式拉高环境变量，稳

## 新手知识点 1：默认值和“上限能力”不是一回事

很多新手会把“默认配置”理解成“系统真实能力的上限”。其实不是。

默认值通常是一个折中：

- 足够快
- 足够常用
- 不会让日常开发太痛苦

而“更稳、更重”的跑法，往往应该作为可选参数保留，而不是直接当默认。

## 新手知识点 2：性能基准要区分“回归检查”和“研究测量”

这两种 benchmark 看起来像一回事，其实目标不同：

- 回归检查
  - 目标是快点发现明显变差
  - 默认应该更轻
- 研究测量
  - 目标是尽量减少噪声、做更可信的结论
  - 应该更重、更慢

这次改动本质上就是把默认值向“回归检查”这一边拉了一点，但没有去掉“研究测量”那条路。

## 这次最重要的经验

性能基础设施如果默认太重，就会让人不愿意经常跑；一旦大家不跑，它再精确也没意义。

更好的策略通常是：

- 默认跑得足够快
- 需要更稳时，再手动把参数拉高
